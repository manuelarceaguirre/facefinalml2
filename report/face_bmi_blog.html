Original Paper

The original Face-to-BMI paper asked a simple computer vision question: can a model infer body mass index from a face image?

Kocabey et al. collected a dataset of social media face images with BMI labels and treated BMI prediction as a supervised regression problem. Their strongest pipeline did not train a new deep network end-to-end. Instead, it used a pretrained CNN as a feature extractor, took high-level face/image features, and trained a support vector regressor on top. The two main feature backbones were generic VGG-Net and face-specialized VGG-Face.

The important part for this project is the evaluation. The paper reported performance using Pearson correlation between true BMI and predicted BMI on a held-out test set. Their headline result was:

Paper modelMale rFemale rOverall r
VGG-Net features + SVR0.580.360.47
VGG-Face features + SVR0.710.570.65

That r = 0.65 number became the target. If we want to say we beat the paper, we need to beat that score on a held-out evaluation that is at least as honest as the original comparison.

Assignment

The class assignment was to replicate and extend the paper, then build a simple real-time web API or demo. In plain English, “beat the paper” means:

Beat the paper = on held-out examples not used for training or model selection, our predictions should linearly agree with true BMI better than the paper's reported best model. Numerically, this means overall Pearson correlation greater than 0.65.

This does not mean the model is medically accurate, fair, or safe for real-world use. A high correlation means that, across the test set, predicted BMI tends to move in the same direction as true BMI. Individual predictions can still be wrong, and BMI itself is a limited health measure.

The main evaluation risk was leakage. The dataset appears to contain paired before/after images of the same person. If one image of a person is in training and the paired image is in test, the model may learn identity-like features rather than general BMI cues. Therefore, the project defines success as beating 0.65 under a pair-safe split.

Data We Have

The dataset was provided as Copy of BMI.zip. Inside it, the canonical metadata file was BMI/Data/data.csv with columns for BMI, gender, official training flag, row id, and image name.

columns = ["unnamed:_0", "bmi", "gender", "is_training", "name"]
image_path = BMI/Data/Images/<name>

The final pipeline used exact canonical image mapping. It did not use fuzzy filename search, because fuzzy matching can accidentally attach the wrong image to the wrong label.

Model Intuition

The original paper's strongest model used face-specialized features. That is the main clue. A generic image model can see color, texture, pose, and face shape, but a face-recognition model is explicitly trained to encode stable facial structure. A modern version of that idea is ArcFace.

The final model uses three complementary frozen embeddings:

Face-recognition idea

ArcFace / InsightFace

Modern face-recognition embeddings. This is the closest conceptual successor to the paper's VGG-Face feature choice.

General vision idea

DINOv2 + ConvNeXt

DINOv2 brings self-supervised visual representation learning; ConvNeXt brings strong supervised ImageNet-style features.

The intuition is not that any single embedding perfectly measures BMI. Instead, each embedding captures a different view of the image: identity/face geometry from ArcFace, broad semantic and shape information from DINOv2, and texture/appearance information from ConvNeXt. Because the dataset is small, frozen embeddings plus regularized regressors are safer than full end-to-end fine-tuning.

The papers/models that motivated the design were:

  • Face-to-BMI: use pretrained CNN features plus SVR for BMI regression.
  • ArcFace: modern discriminative face-recognition embedding.
  • DINOv2: strong general self-supervised visual representation.
  • ConvNeXt: modernized CNN backbone with strong generic image features.

Training

The training pipeline has three stages: build a leakage-safe split, extract frozen features, and train classical regressors. The key split logic was:

df["row_id"] = df["unnamed:_0"].astype(int)
df["pair_id"] = df["row_id"] // 2

# official test split from the dataset
train_pool = df[df["is_training"] == 1]
test       = df[df["is_training"] == 0]

# validation is carved only from train_pool with pair_id grouping
# requirement: no pair_id appears in more than one split

After splitting, the feature matrix concatenated ArcFace, DINOv2, and ConvNeXt:

X_arc   = arcface_features          # 512 dimensions
X_dino  = dinov2_vits14_features    # 384 dimensions
X_conv  = convnext_tiny_features    # 768 dimensions

X = concatenate([X_arc, X_dino, X_conv])  # 1664 dimensions

The strongest simple regressor was RidgeCV with imputation and standardization:

def ridge_model():
    return make_pipeline(
        SimpleImputer(strategy="mean"),
        StandardScaler(),
        RidgeCV(alphas=np.logspace(-4, 4, 41)),
    )

We also tried target-transformed Ridge and PCA-SVR:

def quantile_ridge_model(n_train):
    return TransformedTargetRegressor(
        regressor=ridge_model(),
        transformer=QuantileTransformer(
            n_quantiles=min(512, n_train),
            output_distribution="normal",
            random_state=42,
        ),
    )

pca_svr = make_pipeline(
    SimpleImputer(strategy="mean"),
    StandardScaler(),
    PCA(n_components=256, random_state=42),
    SVR(kernel="rbf", C=10.0, epsilon=0.3, gamma="scale"),
)

The final ensemble was selected using validation predictions only. The test set was used only for final reporting.

# validation-only ensemble selection
selected = top_validation_models
weights = argmax_validation_pearson(selected, nonnegative=True, weight_cap=0.50)
test_prediction = test_predictions[selected] @ weights

Results

The repaired v2 baseline did not beat the paper. That was useful: it showed the leakage-safe protocol was stricter than the exploratory random split. The jump came after adding ArcFace and fusing it with DINOv2 and ConvNeXt.

Demo/API

The final deliverable includes a minimal webcam-only API. YuNet tracks up to six faces in real time, then the heavier model runs when the user presses “Calculate BMI.” The API can also optionally enroll names with consented face captures, so the overlay can show a name plus predicted BMI.

uvicorn api:app --host 127.0.0.1 --port 8000

GET  /             # webcam demo
POST /detect       # lightweight YuNet face boxes
POST /predict_multi # BMI predictions for up to six people
POST /enroll       # optional local face-name enrollment

Limitations

The largest technical limitation is regression to the mean. The model tends to overpredict lower BMI and underpredict very high BMI, especially obesity class 3. This is visible in the BMI-category residuals.

The largest ethical limitation is that face-based BMI prediction is sensitive and potentially biased. This project is an academic replication and critique. It should not be used for medical, employment, insurance, or personal decisions.

The model beating the paper does not make BMI-from-face a safe product. It only shows that modern embeddings and careful evaluation improve a specific benchmark.
